## Reporting a Vulnerability

The GRIDLOCK team takes the security and integrity of user data, hardware keychain persistence, and AI API keys seriously.

If you discover a security vulnerability within GRIDLOCK, please do **NOT** open a public issue. Instead, report it privately to the maintainer:

- **Maintainer**: Anshuman Holkar
- **Email**: anshumanholkar30@gmail.com
- **Subject**: `[SECURITY VULNERABILITY] GRIDLOCK Mobile Architecture`

### What to Include in Your Report
1. Description of the vulnerability.
2. Steps to reproduce the vulnerability (proof-of-concept script, payloads, or screenshots).
3. The affected component (`services/gemini.ts`, `services/backend.ts`, `storage.ts`, etc.).
4. Any potential mitigations or suggested fixes.

We will acknowledge receipt of your vulnerability report within 48 hours and provide a timeline for patching and disclosure.
